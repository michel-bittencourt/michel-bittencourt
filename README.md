<summary><b>Como eu costumo trabalhar</b></summary>
<br>

- Não encerro uma tarefa quando o código apenas funciona. Testo os limites, reviso cenários improváveis e só dou por pronto quando está sólido.
- Prefiro commits pequenos e claros, PRs bem descritos e revisão de código sem ego, porque revisão boa ensina os dois lados.
- Toda otimização começa com uma medição e termina com outra, para provar que a mudança valeu.
- Comunico cedo e com clareza. Se um prazo começar a desandar, o time fica sabendo no primeiro sinal, não na véspera.
- Documento as decisões que tomo, porque arquitetura sem contexto vira enigma para quem chega depois.
- Aprendo melhor construindo, então todo estudo termina em projeto prático, prova de conceito ou melhoria em algo que já existe.

</details>

## 🤖 IA aplicada ao desenvolvimento

Para mim, IA é parte do processo de engenharia, não atalho. Trabalho com desenvolvimento guiado por especificações, agentes para tarefas repetitivas e engenharia de contexto para tirar o melhor de cada modelo, sempre mantendo o entendimento do código comigo.

Na prática, uso IA para revisar meu próprio código, explorar alternativas e documentar decisões. A ferramenta acelera, mas o critério e a responsabilidade continuam sendo meus.
